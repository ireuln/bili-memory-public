# 打包、移植与更新

> 目标：别人拿到一个文件夹/一个 zip 就能跑；想重打包或移植到小众系统的人，知道要改哪里、不能带什么。

## 一、它是什么（先澄清"重编译"）

本工具是 **PowerShell 脚本**，不是编译型程序：

- 没有 `.exe`、没有二进制依赖（除可选的 7-Zip 与浏览器）；
- "重编译"实际是**重新打包**（改脚本/换目录/加启动器），不需要编译器；
- 包里的 `start.cmd` 只是双击入口，真正逻辑在 `*.ps1`。

## 二、支持矩阵

| 系统 / 环境 | 状态 | 说明 |
|---|---|---|
| Windows 10/11 x64 | ✅ 主目标 | PowerShell 5.1 + Edge/Chrome |
| Windows 11 ARM64 | 🟡 可用 | 需 ARM 版 Edge/Chrome；7-Zip 没有 ARM 版时走 ZIP 回退 |
| Windows Server | 🟡 可用 | 需装 Edge/Chrome；无 Store 也能跑 |
| PowerShell 7 | 🟡 部分 | 建议用 `powershell.exe`（5.1）；计划任务/WinForms/COM 在 7 下行为不同 |
| Linux / macOS | ❌ 不支持 | 见"移植要点" |
| 无 Edge/Chrome | ❌ 不能采集 | 查询/报告仍可读已有数据 |

## 三、发布包结构

`build-release.ps1` 生成：

```text
dist\bili-memory-<version>\
  B印象.exe             (thin launcher -> start.cmd)
  B印象-卸载.exe        (thin launcher -> uninstall.ps1)
  start.cmd
  *.ps1
  config.example.json
  version.json
  BUILD-INFO.txt       (版本、commit、仓库/更新链接)
  README.md  LICENSE  NOTICE.md  SUPPORT.md ...
  lang\  lib\  tools\  assets\  docs\
```

`B印象.exe` / `B印象-卸载.exe` 是 C# 薄启动器（源码在 `src\`），不是重写的程序；用 `build-exe.ps1` 重新编译。未签名，SmartScreen/杀软可能提示。

**不包含**：`config.json`、`backup-secret.json`、`status.json`、`run.lock`、`登录态\`、`.secret-patterns`、`.git`、`dist`。

生成：

```powershell
.\build-release.ps1                 # 用 version.json 的版本号
.\build-release.ps1 -Version 0.1.1  # 覆盖版本号
.\build-release.ps1 -NoZip          # 只要文件夹
```

## 四、移植到其他系统：要改什么

| 依赖 | Windows 现状 | 移植替代 |
|---|---|---|
| 浏览器 CDP 启动 | `msedge.exe` / `chrome.exe` 路径 | 换成目标系统的 Chromium 路径 |
| 托盘 | WinForms `NotifyIcon` | 换系统托盘库，或去掉托盘只留 CLI |
| 计划任务 | `ScheduledTasks` 模块 | cron / systemd timer / launchd |
| 快捷方式 | `WScript.Shell` COM | 删除或换桌面环境入口 |
| 压缩 | 7-Zip 或 `Compress-Archive` | `zip` / `7z` / `tar` |
| 路径 | `\`、盘符 | `/`、`$HOME`；注意 `Join-Path` |
| 编码 | 脚本 ASCII，配置 UTF-8 | 保持一致，别让 shell 按本地编码读 |

**最小可移植内核**：`query.ps1` / `report.ps1` / `share.ps1`（只读本地 jsonl）不依赖浏览器与计划任务，最容易先移植。

## 五、重打包规则（给别人发包时）

1. 只复制白名单文件，别把 `config.json` / `登录态\` / 备份密码带进去；
2. 改 `version.json` 的 `version`、`repo`、`releases`；
3. 保留 `LICENSE`、`NOTICE.md`、`docs/第三方代码政策.md`；
4. 跑一次 `tools\check-secrets.ps1`；
5. GPL-3.0：分发二进制/打包版也要提供对应源码；
6. 不要把自己的签名证书、路径、账号信息写进脚本。

## 六、更新

- 仓库：见 `version.json` 的 `repo`
- 发布页：见 `version.json` 的 `releases`（或 `BUILD-INFO.txt`）
- 更新步骤：下载新包 → 关托盘 → 替换脚本/文档 → **保留 `config.json` 与 `DataRoot`** → `start.cmd`
- 没有自动更新、没有联网检查版本；工具不会偷偷下载东西
- 可选的手动检查：`.\check-update.ps1`（只读 GitHub releases API；`-Quiet` 只返回退出码）

### 为什么先不做自动更新

- 未签名脚本自动替换 = 把供应链风险直接接到用户机器上；
- 需要下载校验、回滚、版本锁、失败恢复，工作量不小；
- 现在没有用户基数，先保留 `version.json` + releases 链接，等有人用再加；
- 要做也应是"提示 + 用户确认 + SHA256/签名校验"，而不是静默替换。

## 七、校验

- 发布页如提供 SHA256，下载后先核对；
- 包内 `BUILD-INFO.txt` 记录版本、commit、构建时间；
- 升级前先手动备份一次（`run-task.ps1 -Mode backup`）。
