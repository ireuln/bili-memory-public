# 备份到别处（同步工具 / 网盘 / 远端）

> 默认配置只做两处本地落地。想换成别的工具，不用改代码——**备份包就是普通的 `.7z` 文件**。

## 一、它到底往哪写

两个地方，都在 `config.json` 里：

```json
"ColdBackup": "D:\\bili-backup",
"BackupTargets": [
  { "Path": "D:\\bili-backup",           "Kind": "primary" },
  { "Path": "D:\\OneDrive\\bili-backup", "Kind": "mirror" }
]
```

- `ColdBackup` 是主落点
- `BackupTargets` 里每一项都会被写一份；**同一卷内用硬链接**，不额外占空间
- 跨卷就退化成真拷贝

## 二、方式一：让同步工具盯住目录（最省事）

任何"监视本地文件夹并自动上传"的工具都能用，因为对你来说它只是一个目录：

| 工具 | 做法 | 注意 |
|---|---|---|
| Syncthing | 把 `D:\bili-backup` 加为共享文件夹 | 点对点，不经云端 |
| 坚果云 / Dropbox / MEGA | 把目标写进它同步的目录 | 注意同步客户端自己占的空间 |
| OneDrive（默认） | 已经是这个模式 | — |

改法只需一行——把 `BackupTargets` 里 mirror 的 `Path` 换成被同步的目录：

```json
{ "Path": "E:\\Sync\\bili-backup", "Kind": "mirror" }
```

（`E:\Sync\bili-backup` 指你那个同步工具监视的目录，换成自己的即可。）

> 硬链接只在同一卷生效，所以跨到别的盘时它会老老实实复制一份，这是预期行为。

## 三、方式二：用 rclone 推到远端

适用于 WebDAV / S3 / 对象存储，不适合挂成盘的服务：

```powershell
# 一次性：配置远端
rclone config

# 每次备份后推上去
rclone copy "D:\bili-backup" "myremote:bili" --include "bili-archive-*.7z" --max-age 1d
```

## 四、方式三：备份完成后接自己的动作

**当前没有内置 hook**（有意不加：配置文件里能执行任意命令，等于把配置文件变成执行入口）。

要串起来就在调度层包一层，例如改成你自己的脚本：

```powershell
# wrapper.ps1（放在别处，不要覆盖 run-task.ps1）
$root = 'C:\path\to\bili-history'
& powershell.exe -NoProfile -ExecutionPolicy Bypass -File (Join-Path $root 'run-task.ps1') -Mode backup
if ($LASTEXITCODE -eq 0) {
    rclone copy 'D:\bili-backup' 'myremote:bili' --include 'bili-archive-*.7z'
} else {
    Write-Host 'backup failed, skipping upload'
}
```

然后把计划任务指向 `wrapper.ps1`。**失败就别上传**——否则同步的是半截包。

## 五、三条注意

1. **默认不加密**：包是普通 `.7z`，谁拿到谁能看。**传到云/移动盘前加 `-Encrypt`**（AES-256 + 文件名加密），否则等于把观看史明文放上去。
2. 启用 `-Encrypt` 时，密码在 `backup-secret.json`，永远只留本地，别跟着包一起同步。
3. **保留策略只在本地生效**（删最旧的那 5 份）。云端的旧副本要你自己管——否则三年后云端会攒几百个包。

## 六、检查是否真的生效

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\backup-package.ps1 -Verify
```

它会列出每个目标的实际路径与可写性。改完先跑这个，再动计划任务。
