> 本项目 GPL-3.0。凡引入他人代码，走下面三道门槛；**门槛不是形式，是免责的前提**。

## 一、三道门槛（全满足才可引入）

| # | 门槛 | 判定方式 |
|---|---|---|
| 1 | **许可明确且兼容 GPL-3.0** | 必须找到 `LICENSE` 文件或仓库 API 认定；只有 `package.json` 里的字段不算数，记为"待确认" |
| 2 | **不进入主体程序** | 主体 = 采集 / 归档 / 索引 / 查询 / 备份 / 报告。第三方只能出现在可选模块、独立可执行文件或纯参考资料中 |
| 3 | **两处署名** | `docs/致谢.md`（项目、作者、许可、用途、改了哪里）＋ `README.md` 一句话。只写"感谢开源"不算署名 |

达不到第 1 条：**一行都不能抄**。无许可 = 保留所有权利。

## 三、红区：bilibili-API-collect

2026-01-28，该仓库维护者公开声明收到 B 站委托律所的警告邮件，指控其"通过技术手段对哔哩哔哩平台非公开的 API 接口及其调用逻辑、参数结构、访问控制及安全认证机制进行系统性收集、整理，并以技术文档、代码示例等形式向不特定公众传播"。仓库随即停止维护并删除文档与源码。

对本站的两点含义：

1. **不能引用**：它现在既无许可、也是争议标的，代码与文档都不能进本仓库。
2. **行为重估**：被指控的行为（整理非公开接口 + 参数结构 + 安全认证机制）本身就是风险来源；许可问题只是其中一半，**另一半是这类实现的风险**。本项目的取舍见第四节。

## 四、处置

- 本仓库不包含这类实现，也不描述其接口、参数与认证细节。
- 公开文档不展开参数与认证细节，只写目标、输入、输出与失败症状。
- 若将来引入相关能力，必须去掉认证 / 签名部分，只保留"读取本地已下载文件"。

## 五、自研边界

**必须自研**：采集、归档、索引、查询、报告、备份、分享载荷、草稿脚手架。
**可以外包**：媒体下载执行（第三方下载器）、音视频合并（ffmpeg）、格式解码（若将来做弹幕）。

判断标准很简单：**别人挂了，这个工具还剩不剩核心价值？** 若不剩，那段逻辑就不该是第三方的。
