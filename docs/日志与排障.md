# 日志与排障

> 默认只记关键事件；排障时把 `LogLevel` 改成 `debug`，再复现一次。

## 一、日志在哪

| 文件 | 位置 | 内容 |
|---|---|---|
| 应用日志 | `<DataRoot>\日志\app-YYYYMMDD.log` | 托盘启动、菜单动作、退出；debug 时含路径 |
| 启动器日志 | `%TEMP%\bili-memory-logs\launcher.log` | `B印象.exe` 的启动路径、成功/异常 |
| 批处理日志 | `%TEMP%\bili-memory-logs\start.log` | `start.cmd` 是否进入 setup、是否启动托盘 |
| 卸载器日志 | `%TEMP%\bili-memory-logs\uninstaller.log` | 卸载入口是否成功拉起 |
| 运行日志 | `<DataRoot>\日志\run-<mode>-<时间>.log` | 每次采集/备份的完整 stdout/stderr |

`%TEMP%` 通常是 `C:\Users\<你>\AppData\Local\Temp`。

## 二、普通 vs 详细

`config.json`：

```json
"LogLevel": "normal"
```

- `normal`（默认）：启动、菜单动作、错误；文件很小；
- `debug`：额外记录配置路径、数据目录、脚本动作，用于排障；
- 改完**重启托盘**生效（退出托盘再双击 `B印象.exe`）。

日志按天分文件，不自动删；占空间可手动删旧文件。

## 三、启动失败怎么查

按顺序看：

1. 启动器会先做完整性检查：发行包里有 `SHA256SUMS.txt`，缺失/被改会在中文弹窗列出；
   也可以手动跑 `.\verify-files.ps1`（0 正常 / 1 缺文件 / 2 源码目录无清单）；
2. `%TEMP%\bili-memory-logs\launcher.log` —— EXE 有没有起来、有没有报错；
3. `%TEMP%\bili-memory-logs\start.log` —— 如果走的是 `start.cmd`；
4. `<DataRoot>\日志\app-YYYYMMDD.log` —— 托盘有没有启动；
5. 直接在终端跑：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tray.ps1`，看报错。

如果三个日志都为空、文件也不在，通常是**杀软拦截**，不是脚本错误——见下一节。

## 四、火绒/杀软隔离了 `start.cmd` 或 EXE

这是**误报**：`start.cmd` 里出现 `-ExecutionPolicy Bypass` + 隐藏 PowerShell，是常见恶意脚本特征，火绒会直接隔离。

正确处理（不要关全局防护）：

1. 火绒 → **防护中心 → 隔离区**，找到 `start.cmd` / `B印象.exe`，选择**恢复**；
2. 火绒 → **信任区**，把**整个工具文件夹**（以及 `DataRoot`）加入信任；
3. 如果 EXE 也被拦，同样恢复并信任；
4. 仍不放心：把文件提交火绒“误报反馈”，附上发布页的 SHA256；
5. 重新双击 `B印象.exe`。

注意：

- 不要从隔离区恢复来源不明的同名文件；确认路径是你的工具目录；
- 不要为了运行工具关闭火绒全部防护；
- 如果信任区也不让加，用 `start.cmd` 的等价命令手动跑：`powershell -ExecutionPolicy Bypass -File .\tray.ps1`。

## 五、日志里不要放的东西

- 不会记录 cookie、SESSDATA、`backup-secret.json` 内容；
- `debug` 只多记路径与动作，不记消息正文；
- 发给别人前仍建议扫一眼，删掉真实用户名/路径/标题。

## 六、清理

- `%TEMP%\bili-memory-logs\` 可整个删；
- `<DataRoot>\日志\` 里旧 `app-*.log` / `run-*.log` 可删；
- 删除日志不影响归档数据。
