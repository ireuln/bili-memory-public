# 维护流程（main 是受保护的）

> 从 2026-10-27 起，`main` 开启了分支保护：**任何改动都必须走 Pull Request，维护者本人也不例外**。
> 目的不是防别人，是让每一次改动都留下一条可回看的记录——谁改的、改了什么、为什么。

## 一、日常改动的固定动作

```powershell
# 1. 开分支（名字自己认得就行）
git switch -c docs/xxx        # 或 fix/xxx、feat/xxx

# 2. 改文件、提交
git add -A
git commit -m "docs: ..."

# 3. 推分支（注意：不是推 main）
git push -u origin docs/xxx

# 4. 开 PR 并合并（自己合并自己，批准数为 0）
gh pr create --title "docs: ..." --body "改了什么 / 为什么"
gh pr merge --squash --delete-branch

# 5. 回到最新 main
git switch main ; git pull
```

## 二、规则的具体取值（为什么这样配）

| 设置 | 取值 | 原因 |
|---|---|---|
| 必须走 PR | 是 | 一次推送 = 一条可回看的记录 |
| 必需批准数 | **0** | 单人项目无法自己批准自己的 PR；0 是"要 PR、不要评审"的唯一可行解 |
| 管理员也受约束 | 是 | 否则我自己直推 main 就绕过了，等于没开 |
| 禁止 force-push | 是 | 手滑抹历史不可恢复 |
| 禁止删除分支 | 是 | 同上 |

## 三、被拦了怎么办（错误长这样）

```
remote: error: GH006: Protected branch update failed for refs/heads/main.
remote: - Changes must be made through a pull request.
```

不是权限问题，是**流程**问题。把本地提交挪到分支上再推：

```powershell
git branch rescue/$(Get-Date -Format yyyyMMdd)
git reset --hard origin/main
git switch rescue/...
git push -u origin rescue/...
```

## 四、紧急通道（只在真出事时用）

如果 main 被改坏、而 PR 流程挡住修复（例如需要立刻改 `SHA256SUMS.txt` 止损），可以**临时**关掉保护：

```powershell
gh api -X DELETE repos/ireuln/bili-memory-public/branches/main/protection
# 修完立刻恢复（见下）
gh api -X PUT repos/ireuln/bili-memory-public/branches/main/protection `
  --input protection.json
```

恢复用的 `protection.json`：

```json
{
  "required_status_checks": null,
  "enforce_admins": true,
  "required_pull_request_reviews": { "required_approving_review_count": 0, "dismiss_stale_reviews": false, "require_code_owner_reviews": false },
  "restrictions": null,
  "allow_force_pushes": false,
  "allow_deletions": false
}
```

⚠️ 关保护期间**任何人**（包括恶意的自动化）都能直推 main。用完立刻恢复，别过夜。

## 五、发版（合并之后）

```powershell
.\build-release.ps1                      # 重建 dist 与 SHA256SUMS
powershell -File .\dist\...\verify-files.ps1
gh release create v0.x.0 .\dist\bili-memory-xxx.zip --title "v0.x.0" --notes-file <说明.md>
```

发版前照 [`PR审查清单`](PR审查清单.md) 的必跑三项走一遍；**源码和发布包行为不一致**是这个仓库历史上最大的一类 bug。

## 六、外部 PR

1. 先免费拿 `gh pr diff <编号>` 过一遍 [`PR审查清单`](PR审查清单.md)；
2. 有任何一票否决项 → 关掉并说明原因，不要"改一改再合"；
3. 通过后 squash 合并，合并后 `git log -1 --stat` 核对内容与审查时一致；
4. 合并即表示同意以 GPL-3.0 分发对方贡献（`CONTRIBUTING.md` 已写明）。
