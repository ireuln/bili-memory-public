# 能力说明（首次使用必读）

> 这份文档回答一个问题：**装上这个工具，我到底能得到什么、不能得到什么。**
> 面向第一次接触的人，不假设你懂 PowerShell 或 B 站接口。

---

## 一、它解决什么问题

B 站**不提供**个人观看历史的导出。人会忘，收藏会死。

实测一份 约 1.4 万条的收藏库（样本约数）：**约 2,000 条（15%）已经失效**——视频没了，标题变"已失效视频"，封面链接也挂掉。

这个工具每天自动把这些记下来，存成本地文件，让**未来的你、未来的 AI** 能真正读到，而不是靠回忆。

## 二、装上之后你会得到什么

跑一次（几分钟到半小时，取决于收藏量），产出：

| 产出 | 内容 | 实测规模 |
|---|---|---|
| **观看记录** `观看记录\YYYY-MM.jsonl` | 每条：时间、标题、BV号、UP主、分区、时长、看到第几秒、完成度 | 约 1200 条（接口上限） |
| **收藏总表** `收藏备份\收藏总表.jsonl` | 全部收藏，含收藏时间、是否失效、何时失效 | 约 1.4 万条 |
| **收藏可读表** `收藏备份\*.md` | 每个收藏夹一份表格，可直接看 | 22 份 |
| **封面快照** `封面图\` | 320px 缩略图，**视频没了还能认出是哪条** | 约 1.2 万张 / 110 MB |
| **关注分组** `关注\members.jsonl` | 关注的人、所在分组、特别关注标记 | 约 4,000 人 |
| **近期高频 UP** `关注\recent-top30d.json` | 近 30 天你实际看得最多的 UP | 20 条 |
| **稍后观看** `观看记录\稍后观看.jsonl` | 稍后再看列表，含加入时间 | 133 条 |
| **私信** `私信\` | 会话列表 + 消息（默认关闭，仅本地） | 视你而定 |
| **视频原文件** | **不提供下载** | — |
| **报告** `报告\report-*.md` | 观看时长、分区分布、UP 排行、失效率 | 每月一份 |
| **备份** `bili-archive-*.7z` | 默认不加密；`-Encrypt` 时 AES-256；双目标，保留 5 份 | 约 2.5 MB |

## 三、它能回答的问题

- 我最近在看什么？时间花在哪个分区、哪个 UP 身上？
- 哪些收藏已经废了？一共废了多少？
- 这条视频原来长什么样？（失效后靠封面快照认）
- 我记得看过但搜不到，帮我找出来。
- 我关注的人里，谁半年没动静了？
- 我收藏的东西，按年份/时长是怎么分布的？

## 四、它做不到的（重要）

| 做不到 | 原因 |
|---|---|
| 播放器事件（暂停、拖拽、倍速、弹幕开关） | 接口不返回，只有采样快照 |
| 点赞/投币的**精确时间** | 接口只给"是否点过"，没有时间戳 |
| 超过约 1200 条的历史回溯 | 接口硬上限，只能靠每天采累积 |
| 关注某人的**加入时间** | 该字段返回空字符串 |
| 动态流（新发的想法/图片） | 接口需要额外参数，尚未验证 |

详见 [`限制与不做.md`](限制与不做.md)。

## 五、它怎么工作（30 秒版）

常见做法是让你交出 cookie / SESSDATA，脚本拿着它去请求——等于把账号控制权交出去。

这个工具反过来：

1. 开一个**专用浏览器**（独立 profile），首次你扫码登录一次；
2. 采集时通过浏览器的调试协议，**让浏览器自己去请求**；
3. 数据回来后立刻关浏览器。

**凭据始终不出浏览器**，脚本拿不到也不需要。

## 六、日常运行什么样

| 任务 | 时间 | 耗时 |
|---|---|---|
| 观看记录 | 每天 04:00 | 约 35–45 秒 |
| 收藏巡检 | 每周日 05:00 | 约 20 分钟 |
| 关注分组 | 每周日 05:40 | 约 2 分钟 |
| 备份 | 每周日 06:00 | 约 10 秒 |

平时只有一个**托盘图标**常驻：绿色=上次成功，黄色=正在采集，红色=失败，灰色=没跑过。

- **双击图标** → 弹出「数据速览」小卡片：累计观看、本月、收藏、近 7 天与活动天数、失效数、占用大小；再点一次或点别处关闭。
- 卡片顶部有一条**状态带**：正在跑长任务时是琥珀色，写「正在采集：收藏夹 · 已用 03:12」并**每秒走秒**；
  成功后变绿并显示完成时间，失败变红。**任务一开始就会自动弹这张卡片**，8 秒内不会因为点了别处而消失。
- 卡片右上角有 **×**，随时点掉；Esc 也行。若 `status.json` 说“运行中”但其实没有采集进程（例如包装器异常退出），卡片显示红色
  「上次运行未正常结束」，不会一直骗你“正在采集”。
- **右键** → 菜单按用途分组（采集 / 产出 / 备份 / 查看），**设置单独一组**，在子菜单里，避免跟"立即采集"这类长任务放一起误点。
- **提示音**：默认「柔和」——自家一段 200 ms 短音，峰值约 -21 dBFS，比 Windows 警告音轻很多；可在 设置 ▸ 计划与设置 切成「Windows 系统音」或「关闭」。
  > 为什么要换：Windows 的弹窗提示音由**图标**触发，程序无法单独调小；所以柔和模式下弹窗不带图标，改在标题写「注意：」「错误：」。

资源占用：采集时浏览器约 466 MB + PowerShell 约 300 MB，跑完即释放。托盘常驻约 99 MB。

## 七、隐私与安全

- **不联网上传**任何数据；无遥测、无统计上报
- 常规外部访问是 `bilibili.com` 自己的接口与图床；只有手动点"检查更新"时，`check-update.ps1` 才会只读访问 `api.github.com`
- 登录态在 `登录态\` 目录，**等价于你的账号**，不要拷贝/上传/分享
- 私信内容只存本地，**不进备份包**，也不进分享载荷
- 备份默认**不加密**（明文 `.7z`）；启用 `-Encrypt` 时密码在 `backup-secret.json`，该文件不进仓库。离机备份前请看 README 的备份一节与 [`SECURITY.md`](../SECURITY.md)

## 八、使用者需要承担什么

- 自动化访问可能违反平台用户协议，**风险自负**
- 高频采集（`-Sampling`）可能导致限流或账号失效，**默认关闭**
- 接口随时可能变更，失效属于预期内情况，不是缺陷
- 导出内容若分享出去，后果由发布者承担；**不要公开再分发**他人的作品（封面、标题都属于原作者）

## 九、第一次使用的三步

```powershell
# 1. 安装（自动挑盘、生成配置）
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1

# 2. 扫码登录（只做一次，必须本人）
powershell.exe ... -File .\collect.ps1 -Login

# 3. 跑第一次
powershell.exe ... -File .\run-task.ps1 -Mode history
powershell.exe ... -File .\run-task.ps1 -Mode fav -TimeoutMinutes 90
```

然后按需选择自动化：

```powershell
powershell.exe ... -File .\report.ps1                 # 出一份报告看看
powershell.exe ... -File .\register-task.ps1 -DryRun  # 看会注册哪些任务
powershell.exe ... -File .\register-task.ps1          # 按 config.json -> Automation 应用
```

每一项都可以单独设 `scheduled` 或 `manual`；`Startup` 控制托盘是否开机自启。不想让任何东西自动跑，就把对应项改成 `manual`，或者 `register-task.ps1 -Unregister`。
