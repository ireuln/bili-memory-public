# 功能清单

> 公开前的盘点。**已有**都跑过；**可扩展**都只是判断，没写代码。
> 代价用"人日"和"本项目的真实工期"两种口径，别拿它当承诺。

| | 收藏夹（全部夹、失效时间线、320px 封面快照） | ✅ 全量约 20 分钟 |
| | 关注分组（特别关注 + 自建分组 + 近 30 天高频 UP） | ✅ 约 2 分钟 |
| | 稍后观看（含加入时间） | ✅ 133 条级 |
| | 私信（会话 + 消息，**默认关闭**） | ✅ 仅本地 |
| **调度** `run-task.ps1` | 单实例锁 / 硬超时 / 有限重试 / 让路不杀 | ✅ |
| **查询** `query.ps1` | 按时间窗、UP（名或 UID）、分区、标题、BV、夹筛选 | ✅ 只读不联网 |
| | `-Text` 关键词检索（标题/简介/UP/分区/夹），首次建索引约 6 MB | ✅ 后续约 0.5 秒 |

## 二、可以扩展（按性价比排序）

| 功能 | 价值 | 代价 | 风险 | 建议 |
|---|---|---|---|---|
| **关键词 → 批量下载** | 高 | 0.5 小时 | 风控 | ✅ 值得，但下载交给外部工具 |
| **分 P 批量** | 中 | 0.5 小时 | 低 | ✅ 顺路做 |
| **合集批量**（`ugc_season`） | 中 | 1 小时 | 低（一次 view 调用） | ✅ 顺路做 |
| **同 UP 同类** | 中 | 1.5 小时 | 中（`-352` 风控） | 🟡 要先定义"同类" |
| **UP 休眠检测**（死号/沉睡/活跃） | 高 | 1–2 小时 | 中（风控） | 🟡 依赖上一条 |
| **评论标记** | 低（对归档价值有限） | 2 小时 | 高（每条视频一次请求） | ❌ 不建议 |
| **动态流** | 中 | 2–3 小时 | 高（接口 + 风控） | 🟡 风险高于收益 |
| **弹幕 / 字幕导出** | 中 | 1–2 天（protobuf） | 中 | ❌ 不在范畴 |
| **直播录制** | 低 | 2–3 天 | 高 | ❌ 不做 |
| **Web 界面** | 中 | 3–5 天 | 低 | 🟡 违背"离线小工具"定位 |
| **多账号** | 低 | 1 天 | 低 | ❌ 没需求 |
| **移动端导出**（把报告推到手机） | 中 | 2 小时 | 低 | 🟡 走网盘即可 |
| **自动生成 Suggestions 分组** | 中 | 2 小时 | 低 | 🟡 只写本地建议，不碰平台 |

## 三、明确不做

| 不做 | 原因 |
|---|---|
| 上传/同步归档到本工具自己的服务器 | 违背"不联网"的定位 |
| 修改 B 站端的分组、收藏、关注 | 写接口需登录态，必触发风控 |
| 破解会员 / 绕过付费 / 去 DRM | 法律与道德红线 |
| 批量抓取他人数据 | 同上 |
| 自动发送私信 | 不可逆动作，风险不可控 |

## 四、判断标准

新增一个功能前问三句：

1. **它读的是本地文件，还是又去打接口？** 前者成本低、风险低。
2. **失败时会不会破坏已有数据？** 会的话就不该进计划任务。
3. **别人关掉这个仓库，用户还剩什么？** 核心价值不能依赖某一项外链功能。
