# 限制与不做的事

> 这份文档专门记录"**做不了 / 不好做 / 不该做**"的东西，以及原因和替代方案。
> 目的是让后来的人（和 AI）不要重复踩同一个坑，也不要许下做不到的承诺。

---

## 一、做不到（接口层面就没有）

| 需求 | 为什么做不到 | 现有替代 |
|---|---|---|
| ~~私信内容~~ | ✅ **已更正：接口可用**，`get_sessions` + `fetch_session_msgs` 实测 `code:0` | 已实现 `-Dms`（默认关闭），只存本地 |
| **评论** | 公开数据，但只能**按视频**查（按视频查询的评论接口），无"我发过的评论"总表 | 可行：对指定视频抓评论并打标记；成本按视频数计 |
| **播放器事件**（暂停/拖拽/倍速/弹幕开关） | 属于前端事件，接口不返回 | 只能靠**高频采样**近似（默认关闭，见下） |
| **点赞/投币的精确发生时间** | 接口只给"当前是否点过"，不给时间戳 | 只能记录"哪次采集首次发现"，精度＝采集间隔 |
| **关注某人加入的时间** | 关注分组接口返回的 `follow_time` 字段实测是**空字符串** | 未找到可用入口；需要额外参数的关注列表接口可能给，但未验证 |
| **已删除的视频内容** | 视频没了就是没了 | 只能保住**标题 + 封面 + 时间**这几样元数据 |

## 二、不好做（能做但代价高）

| 需求 | 代价 | 说明 |
|---|---|---|
| **点赞/投币状态** | 每条视频 1–2 次请求 | 1,200 条观看记录 ≈ 1,500+ 请求，风控风险高。建议只对"特别关注"的 UP 做 |
| **全量失效复查** | 约 **20 分钟** / 22 个夹 | 每页 20 条、1.2 秒间隔，无法更快。可用 `-FavCheck`（不下载封面）省一半时间 |
| **动态流（新视频/文字/图片）** | 接口未验证 | 动态流接口大概率需要额外参数。未做，不要假设它可用 |
| **跨 1,200 条的历史回溯** | **不可能** | 接口有硬上限，只能靠每天采累积。断一天永久少一天 |

## 三、不该做（法律边界，不是功能边界）

下面这些不是"工具限制"，是**使用者的行为边界**。做了，由使用者自行承担后果；作者不提供法律意见，也不能替使用者承担其行为的责任。

| 不要做 | 可能触发 |
|---|---|
| **自动分享到社交平台** | 发布责任由使用者承担（见第八节）；工具只生成载荷，不代发 |
| **批量下载、转存、再分发他人的视频、封面、字幕、弹幕** | 著作权投诉、民事索赔 |
| **把归档（标题、UP 名、封面、观看史）公开上传到网盘、群、网站或训练语料** | 著作权、个人信息、平台投诉 |
| **抓取他人的观看记录、收藏、关注、私信** | 《个人信息保护法》、平台规则 |
| **绕过付费 / 权限 / DRM / 地区限制** | 违法，且会让整个项目失去正当性 |
| **商业化：售卖数据、代抓、付费服务** | 不正当竞争、著作权 |
| **对抗风控（提频、绕限流等）** | 账号封禁、接口封停 |

现实中最常见的是**限流、封号、接口失效、投诉下架**；民事索赔与刑事风险通常出现在规模化、商业化或公开传播的场景。

## 四、有风险但可选

| 功能 | 风险 | 默认 |
|---|---|---|
| `-Sampling <分钟>` 常驻采样 | 请求量 ×96，可能触发风控 | **关闭**，需手动输 `YES` |
| 用 Cookie/SESSDATA 替代浏览器 | 凭据明文落盘，泄露即可控号 | **不提供** |
| 备份密码写在配置文件（仅 `-Encrypt`） | 7z 密码会出现在进程命令行 | 已知限制，见下 |

## 五、已知缺陷（不打算修，或暂未修）

| 缺陷 | 影响 | 为什么先不修 |
|---|---|---|
| 7z 密码通过命令行传递（仅 `-Encrypt`） | 本机其他进程理论上可读 | 改为 .NET AES 需要重写加密模块，收益 < 成本 |
| 48px 图标由 128px 缩放 | 200% DPI 下比例略有偏差 | 多数用户 100% 缩放，看到的是 16px |
| 收藏总表按视频去重 | 同一视频在多个夹只保留最后一个归属 | 改成多归属会破坏现有读取方 |
| `is_finish` 字段不可用 | 已废弃，改用 `completion` / `completed` | 保留字段仅为兼容旧数据 |

## 六、如果你要接手改

优先级建议：

1. **关注时间 / 动态流**——需要额外参数，未验证；不建议为此引入相关实现
2. **加密模块换 .NET AES**——消除命令行密码泄露
3. **查询接口 `query.ps1`**——让其他 AI 按时间/UP/分区取数，而不是自己解析 jsonl

不要把时间花在：图标细节、托盘动效、Markdown 排版——那些不影响数据价值。

## 七、私信模块的边界（2026-10-27 追加）

`-Dms` 已实现，但有三条硬约束：

1. **只存本地**。私信正文同时包含对方的话，属于**双方**的通信，因此：
   - 不进备份包（`backup-package.ps1` 只打包观看记录与收藏）
   - 不进任何分享载荷
2. **默认关闭**，不进入任何计划任务；需要时手动 `-Dms -DmsLimit N`
3. **只读不写**。AI 回复功能只生成草稿（你复制粘贴），**不提供自动发送**——自动发消息属于另一个风险等级（平台判定为机器人行为）。

## 八、自动分享的责任归属（2026-10-27 追加）

按使用者要求调整：工具提供**分享载荷**（自包含文件 + 一段可直接粘贴的说明），是否发布、发布到哪、后果如何，**由使用者自负**。工具本身不代发、不持有任何第三方平台凭据。
