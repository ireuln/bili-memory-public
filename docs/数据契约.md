# 数据契约（Data Contract）

> 给"其他程序 / 其他 AI"看的说明。**读取时优先认文件，不要解析控制台输出。**

## 版本

| 项 | 值 |
|---|---|
| 契约版本 | `1` |
| 兼容策略 | 只**增字段**不删不改语义；破坏性变更才升到 `2` |
| 版本号位置 | 每个结果文件里的 `schema` 字段 |

读取方应先读 `schema`，不等于自己支持的版本时降级处理（忽略未知字段即可）。

---

## 文件角色

| 文件 | 路径 | 谁写 | 用途 |
|---|---|---|---|
| 观看记录 | `<DataRoot>/<History>/YYYY-MM.jsonl` | 采集器 | **主数据**，只追加 |
| 收藏总表 | `<DataRoot>/<Fav>/<masterFile>` | 采集器 | **主数据**，每次全量重写 |
| 收藏可读表 | `<DataRoot>/<Fav>/*.md` | 采集器 | 给人看，不要给程序解析 |
| 运行结果 | `<DataRoot>/last-result.json` | 采集器 | **最近一次采集的机器可读结果** |
| 任务状态 | `<ProjectRoot>/status.json` | 执行器 | 给托盘/守护进程看 |
| 观看游标 | `<DataRoot>/<History>/state.json` | 采集器 | 增量位置，勿手改 |
| 收藏进度 | `<DataRoot>/<Fav>/<progressFile>` | 采集器 | 断点续跑，勿手改 |
| 热度快照 | `<DataRoot>/<Heat>/<heatFile>` | 采集器 | **时间序列**，一天一条，只追加/覆盖当天 |
| 详情补全 | `<DataRoot>/<Detail>/<detailFile>` | 采集器（`-Enrich`） | 逐条补的慢变信息，一条一行 |
| 报告摘要 | stdout（`report.ps1 -Json`） | 报告器 | 一次性摘要 |

`<DataRoot>`、各子目录名、`<masterFile>`、`<heatFile>`、`<progressFile>` 都在 `config.json` 里，**不要硬编码**。

## 观看记录（`YYYY-MM.jsonl`，一行一条）

| 字段 | 类型 | 单位 | 可为空 | 说明 |
|---|---|---|---|---|
| `view_at` | int | Unix 秒 | 否 | 观看时刻（本地时区解释） |
| `bvid` | string | — | **是** | BV 号；PGC（番剧/影视）条目通常为空 |
| `aid` | int | — | 否 | av 号，`bvid` 为空时的兜底标识 |
| `title` | string | — | 否 | 视频标题（失效后可能是"已失效视频"） |
| `author` | string | — | 是 | UP 主昵称；PGC 条目为空 |
| `author_mid` | int | — | 是 | UP 主 UID；PGC 条目为 0 |
| `tag` | string | — | 是 | 分区名；PGC 条目为空 |
| `duration` | int | 秒 | 否 | **视频总长，不是观看时长** |
| `progress` | int | 秒 | **是** | 看到第几秒；`-1`/缺失表示未知 |
| `is_finish` | int | 0/1 | 否 | ⚠️ **已废弃**，实测 1199 条里仅 1 条为 1，不要使用 |
| `completion` | float | 0–1 | **是** | 观看完成度 = `progress / duration`（上限 1）；`progress` 无效时为 null |
| `completed` | bool | — | 否 | `completion >= 0.9` 时为 true；无法计算时为 false |
| `videos` | int | 个 | 否 | 分 P 数 |
| `business` | string | — | 否 | `archive` / `pgc` 等 |

### 使用警告

- **不要用 `duration` 求和当观看时长**，那是""视频有多长""。观看时长用 `progress` 求和。
- **`is_finish` 已废弃**，请改用 `completed` / `completion`。
- `completion` 与 `completed` 是 v0.1.0 之后新增的字段：**更早的行没有这两个字段**，读取方应按 `progress / duration` 自行计算兜底。
- 完成度 = `progress / duration`，需先过滤 `progress > 0`。
- 同一 `bvid` 可能出现多条（看了多次），这是真实行为，不是重复数据。
- 数组**不保证按时间排序**（B 站会混入旧的 PGC 条目），读取方需自行排序。

## 收藏总表（一行一条）

| 字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `folder_id` | int | — | 收藏夹 ID |
| `folder` | string | — | 收藏夹名 |
| `bvid` / `aid` | string / int | — | 视频标识 |
| `title` | string | — | 标题（失效后为"已失效视频"） |
| `upper` / `upper_mid` | string / int | — | UP 主 |
| `duration` | int | 秒 | 视频总长 |
| `pubtime` | int | Unix 秒 | 视频发布时间 |
| `fav_time` | int | Unix 秒 | **收藏时间** |
| `attr` | int | 位掩码 | 原始属性；`attr & 1` 通常表示失效 |
| `invalid` | bool | — | 已判定的失效标记 |
| `first_seen` | string | 本地时间 | 本工具第一次看到它的时间 |
| `last_seen` | string | 本地时间 | 最近一次确认仍在收藏夹的时间 |
| `invalid_since` | string | 本地时间 | **失效被首次观察到的时间**（空=未失效） |
| `intro` | string | — | 简介，截断到 120 字符 |
| `link` | string | — | 原始链接 |
| `cover` | string | — | 封面 URL（可能会失效） |
| `play` | int | 次 | 播放数（收藏列表接口免费带回，非精确实时） |
| `danmaku` | int | 条 | 弹幕数（同上） |
| `fav_count` | int | 次 | 该视频被收藏的总次数（**不是你的收藏**） |
| `stats_at` | string | 本地时间 | 上面三个数最后一次刷新的时间 |

### 关键语义

- 总表**按视频去重**：同一条视频在多个夹里，只保留最后一次出现的 `folder`。想按夹统计请用 `folder` 字段，别期待跨夹重复。
- `invalid_since` 是一次"观测"时间，不是平台判定失效的准确时间（取决于采集频率）。
- 失效条目在采集时**不再更新封面**，但已存的封面文件会保留。

## `last-result.json`

```json
{
  "schema": 1,
  "mode": "history",
  "exit": 0,
  "finished": "2026-10-27T15:31:19+08:00",
  "pages": 3,
  "fetched": 6,
  "written": 0,
  "total": 1201,
  "lastViewAt": 1793080094
}
```

| 字段 | 说明 |
|---|---|
| `mode` | `history` / `fav` |
| `exit` | 0 成功；非 0 见脚本退出码约定 |
| `fetched` | 本次从接口取到的条数 |
| `written` | 实际新增写入磁盘的条数（去重后） |
| `total` | 归档累计条数 |

## 退出码约定

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 未分类错误 |
| 4 | 接口返回错误或未登录 |
| 5 | 过滤后没有可采集的收藏夹 |
| 8 | 已有采集进程在跑（执行器让路） |
| 9 | 拿不到单实例锁 |
| 124 | 超时被强杀 |

## `query.ps1` 输出（查询信封）

```json
{
  "schema": 1,
  "generated": "2026-10-27 17:51:17",
  "query": {
    "from": "", "to": "", "up": "", "tag": "", "title": "", "bvid": "",
    "folder": "", "source": "history", "sort": "time", "ascending": false, "limit": 0
  },
  "matched": 0,
  "returned": 0,
  "items": []
}
```

| 字段 | 说明 |
|---|---|
| `query` | 原样回显本次筛选条件，便于复现 |
| `matched` | 过滤后、截断**前**的条数 |
| `returned` | 实际返回条数（受 `-Limit` 约束） |
| `items[].source` | `history` / `fav` |
| `items[].time` | Unix 秒：观看时间（`view_at`）或收藏时间（`fav_time`） |
| `items[].tag` | 仅 history；收藏行恒为空串 |
| `items[].folder` | 仅 fav；history 行恒为空串 |
| `items[].progress` / `completion` / `completed` | 仅 history；无有效 `progress` 时为 `null` / `false` |
| `items[].invalid` | 仅 fav；history 行恒为 `false` |

### 使用要点

- 两种来源**字段名一致**，读取方不必按来源写两套解析；缺失值统一是 `null` 或空串。
- 默认按 `time` **倒序**（最新在前）；`-Ascending` 正序；`-Sort completion|duration` 同理倒序。
- `-Tag` 配 `-Source fav` **恒为空结果**（收藏数据没有分区字段），这是契约，不是 bug。
- `-From`/`-To` 只给日期时，`-To` 覆盖当天 23:59:59。
- 不要自己再解析 jsonl：排序、去重口径、`completion` 兜底都在 `query.ps1` 里，复制一份必然走样。

## `share.ps1` 数据包

`<DataRoot>/<Share>/<period>/payload/` 下：

| 文件 | 内容 |
|---|---|
| `watch.jsonl` | 时间窗内的观看记录，字段同 `query.ps1` 的 `items[]`（去掉 `source` / `link`） |
| `favorites.jsonl` | 可选（`-IncludeFavorites`）：时间窗内收藏，额外含 `folder` / `invalid` |
| `summary.json` | 聚合统计：`watch.count/hours/avg_completion/active_days`、`top_ups`、`top_tags` |
| `manifest.json` | `files[]` 每项的 `name` / `bytes` / `sha256`，用于校验完整性 |
| `README.md` | 给人读的字段说明 |

### 关键点

- `summary.json` 的 `avg_completion` 是 **0–1 小数**（`query.ps1` 里是同名字段，也是 0–1）。
- `summary.json` 的 `titles_included` 为 `false` 时，`title` 已被替换为占位文字。
- 数据包**不含**私信、登录态、封面图片；`manifest.json` 里的哈希覆盖同目录其它文件，不含自身。
- 这是给人或给别的 AI 读的导出物，**不是**备份格式；完整备份请用 `backup-package.ps1`。

## `drafts.ps1` 回复草稿契约

三个文件，都在 `<DataRoot>/<Dms>/<draftsDir>/` 下。**这一层永远不进备份包与分享载荷。**

### `queue.json`（只读会话元数据，不含正文）

```json
{
  "schema": 1,
  "generated": "2026-10-27 18:13:39",
  "sessions": 2,
  "waiting": 2,
  "items": [
    { "talker_id": 448165099, "last_ts": 1793092605, "last_at": "2026-10-27 17:16",
      "last_from_me": false, "unread": 1, "days_silent": 0.0 }
  ]
}
```

`items` 只含"最后一句是对方说的"会话，按 `last_ts` **升序**（最久没回的排前面）。

### `<id>.ctx.json`（上下文包）

| 字段 | 说明 |
|---|---|
| `turns[]` | 最近 N 条（`Drafts.contextTurns`），每条 `ts` / `role`(`me`/`them`) / `kind`(`text`/`other`) / `text` |
| `last_from_them` | 对方最后一句，没有则为 `null` |
| `constraints.max_chars` | 草稿字数上限 |
| `constraints.auto_send` | 恒为 `false`——工具没有发送能力 |
| `reply_file` | 期待回填的文件名 |

非文本消息（卡片/分享）的 `kind` 为 `other`，`text` 取卡片标题并加 `Drafts.shareLabel` 前缀，解析不出就退化为 `[<msg_type>]`。

### `<id>.reply.json`（由人或外部 AI 填写）

```json
{ "schema": 1, "talker_id": 448165099, "text": "回复正文" }
```

`-Validate` 的判据：`schema == 1`、`talker_id` 与目录中的 id 一致、`text` 非空且不超过 `max_chars`、不含残留的 `{{ }}`。失败退出码 3。

## 热度快照（`<heatFile>`，一行一条，一天一条）

收藏列表接口在**同一个响应**里就带着播放/弹幕/收藏数，所以这里不产生额外请求。但"最新值"没有意义——要看的是曲线，所以单独存成时间序列。

| 字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `bvid` | string | — | 主键（与收藏总表一致） |
| `date` | string | `YYYY-MM-DD` | 快照日期（**本地时区**） |
| `ts` | int | Unix 秒 | 实际采集时刻 |
| `view` | int | 次 | 播放数 |
| `danmaku` | int | 条 | 弹幕数 |
| `fav` | int | 次 | 全站收藏数 |
| `source` | string | — | `fav`（收藏列表）；后续机型/接口会另标 |

### 关键语义

- **去重键是 `(bvid, date)`**：同一天内重跑只覆盖当天那一条（数值只会往前涨），换一天才追加。
- 文件是**原子替换**写的（先写 `.tmp` 再换名），断电不会留下半行。
- **体积护栏**：`config.json` 里 `HeatMaxRows`（默认 5000）限制一次运行最多**新增**多少条；已达上限的只更新不新增。`HeatEnabled: false` 可整体关闭。
- 新增顺序按 `fav_time` 倒序——真被截断时，丢的是最老的尾巴，不是刚收藏的。
- **存量补不回来**：历史播放量没有接口可查，只能从开始采集那天起累积。
- 失效条目（`invalid: true`）不写快照。

## 详情补全（`<detailFile>`，一行一条，按 `bvid` 去重）

只在显式加 `-Enrich` 时产生。数据来自 `GET /x/web-interface/view/detail?bvid=`，**一次请求把这些全带回**（约 300 KB）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `bvid` | string | 主键 |
| `title` | string | 标题（采集时刻） |
| `desc` | string | **简介全文**（收藏总表里那份截断到 120 字符） |
| `pubdate` | int | 发布时间（Unix 秒） |
| `tname` | string | 分区名 |
| `owner` / `owner_mid` | string / int | UP 主 |
| `owner_face` | string | **UP 头像 URL** |
| `width` / `height` / `rotate` | int | **源分辨率**（不是可播放档位；4K 源就是 3840×2160） |
| `song` / `music_id` | string | **自动识曲**的歌名与音乐 ID（来自 `Tags[]` 中 `tag_type="bgm"` 的那条；没有就是空串） |
| `view` / `danmaku` / `reply` / `like` / `coin` / `favorite` / `share` | int | 8 个统计数（同时写入热度快照，`source="detail"`） |
| `enriched_at` | string | 这条详情最后一次刷新的本地时间 |

### 关键语义

- **额度**：`config.json` 的 `EnrichMax`（默认 **300** 条/次）与 `EnrichDelayMs`（默认 600 ms）。队列按 `enriched_at` 轮转——**没补过的优先，补过最久的排在后面**，所以不需要游标，也不会永远只补同一批。
- **必须显式开启**：`collect.ps1 -Enrich`（历史模式、收藏模式都支持）。默认关闭，因为它每补一条就是一次真实请求。
- 只用公开接口，**不带登录态**：会员专享 / 私享视频会失败并记一条 WARN，下次轮转再试。
- 失效条目（`invalid`）不补。
- `song` 只对"平台已经识曲"的视频有值；没有就是空串，不代表采集失败。

## 关注（`members.jsonl`，一行一个人）

| 字段 | 类型 | 说明 |
|---|---|---|
| `tagid` | int | 分组 ID；`-10` = 特别关注 |
| `tag` | string | 分组名 |
| `mid` / `uname` | int / string | 用户标识与昵称 |
| `sign` | string | 个性签名（可能为空） |
| `official` | int | 认证类型；`-1` = 无 |
| `vip` | int | 大会员类型 |
| `follow_time` | int | **关注时间（Unix 秒）**；`0` = 未知 |

### 关键语义

- `follow_time` **不来自批量接口**：分组接口里该字段为 `null`，只有逐个查询关注关系（字段名 `mtime`）才有值。
- 因此它**默认关闭**：`config.json` 的 `FollowTimeMax`（默认 `0`）。开启后每次运行最多补 N 个人，已补过的（`> 0`）跳过，大账号分几次运行补齐。
- 一人的代价 = 一次请求（间隔 700 ms）。关注 200 人的账号，首次补齐约 2.5 分钟。

## 给下游程序的建议

1. 只读 `.jsonl` 与 `last-result.json`，**不要解析 `.md`**（那是给人看的，随时改版）。
2. 以 `view_at` / `fav_time` 排序，不要相信文件顺序。
3. 用 `bvid` 为主键，缺失时退回 `aid`，再退回 `title`。
4. 任何"用户画像"结论都要附**样本量与时间窗**，因为观看记录只覆盖最近约 1200 条。
