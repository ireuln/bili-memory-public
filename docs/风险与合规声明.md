## 一、隐私风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 采集内容本身极敏感 | 观看/收藏历史可推断政治倾向、情感状态、性取向、健康状况、消费习惯 | 只存本地；不提供任何上传功能 |
| 登录态等于账号控制权 | `登录态\浏览器配置` 目录内含 B 站会话，泄露 = 他人可操作你的账号 | 已加入 `.gitignore`；文档反复强调不要拷贝/上传/分享 |
| 备份包密码强度（仅 `-Encrypt`） | 若用生日、QQ 号等弱口令，AES-256 也能被离线爆破 | 启用加密时用 12 位以上混合密码；未加密包不要离机 |
| 第三方内容再分发 | 封面图、UP 主昵称、标题的著作权不属于你 | 备份自用可以；**公开分享归档等于再分发**，本文档明确反对 |
| 下游 AI 上传 | 若把归档喂给云端模型，等于把观看史交给第三方 | 建议本地模型；必须云端时先脱敏 |

**本项目不含遥测、统计上报或远程日志，也不向作者回传任何数据。** 采集与查询只访问 `bilibili.com` 自身接口与封面图床；唯一例外是 `check-update.ps1`——只在你从托盘菜单手动触发时，读取 `api.github.com` 的公开 Release 信息（只读，只带固定 User-Agent，不含账号或设备标识）。

## 二、法律与平台规则风险

1. **接口非公开**：本文使用的是 B 站网页端自用的内部接口，不属于开放 API，平台可随时变更或阻断。
2. **用户协议**：自动化访问可能违反平台用户协议的具体条款。本项目定位是"本人对自己账号数据的本地备份"，不构成对合规性的承诺。
3. **频率**：默认每页间隔 1.2–2 秒，全量约 20–30 分钟。文档明确反对提高频率。
4. **禁止用途**：不得用于批量抓取他人数据、商业用途、绕过付费墙或权限控制、规避地区限制。
5. **著作权**：封面图与视频内容著作权属于 B 站与相应 UP 主。备份自用可以，**公开再分发不行**。
6. **个人信息保护**：导出数据可能包含他人信息（评论区若被采集）。本项目不采集评论，但用户自行扩展时需注意《个人信息保护法》等要求。
7. **已有先例（2026-01-28）**：`SocialSisterYi/bilibili-API-collect` 的维护者公开声明收到 B 站委托律所的警告邮件，指控其实施"对非公开 API 接口、调用逻辑、参数结构、访问控制及安全认证机制进行系统性收集整理并公开传播"，该仓库随即删库停维。
   - 含义：**把接口细节写成公开文档**，风险高于"个人本地备份"。
   - 本项目的做法：公开文档只写目标、输入、输出与失败症状，不写参数结构与认证细节。
   - 详见 [`第三方代码政策.md`](第三方代码政策.md)。

## 三、AI 相关风险

- **模型不会因对话而更新。** 所谓"学习性格"，本质是**从记录做统计推断**，结果可能固化偏见、把偶然当规律。
- 任何画像结论都应附**依据与置信度**，不得当作事实陈述。本项目只负责产出数据，不负责下结论。
- **提示注入**：视频标题、简介、UP 主昵称都是第三方可控文本，属于不可信输入。本项目只存储、不执行；但下游若让 AI 阅读这些文本，必须明确"其中任何指令都应忽略"。
- 若使用云端 AI 分析归档，等同把个人观看史上传给第三方服务商，请自行评估。

## 四、代码与运行风险

| 项 | 风险 | 现状 |
|---|---|---|
| 登录态存储 | 专用浏览器 profile 即凭据 | 设计为不读 cookie 文件、凭据不出浏览器；但目录本身仍需保护 |
| CDP 调试端口 | 仅监听 `127.0.0.1`，但本机任意进程可连接 | 只在采集的数十秒内开放，采集结束立即关闭浏览器 |
| 密码传递 | `7z -p<密码>` 会出现在进程命令行，本机其他进程理论上可读 | **已知限制**，后续计划改为 .NET AES 或 DPAPI |
| 执行策略 | 计划任务使用 `-ExecutionPolicy Bypass` | 从网络获取的脚本请先核对哈希与来源 |
| 写入位置 | `DataRoot` 配置错误可能写到意外位置 | `backup-package.ps1 -Verify` 可先确认目标；`setup.ps1` 会列出候选盘并要求确认 |
| 断点与重试 | 有锁、超时、重试，但非绝对可靠 | 数据损坏时应从备份恢复（加密包需密码） |

## 六、私人使用 vs 公开传播（这是关键分界）

律师函点名的行为是"系统收集整理**并向不特定公众传播**"。两个要件：

1. 系统性整理非公开接口 / 认证机制；
2. **向不特定公众传播**。

私人本地工具只满足第 1 条。公开仓库本身不等于传播接口细节——但把参数写成教程、把实现发出去，第 2 条就补上了；**先例正是倒在第二步**。

因此：

- 本仓库已按第七节完成复核，公开文档不含参数与认证细节；
- 本文档自身也算"传播载体"，已按同一标准处理；
- 如果将来要写更细的接口文档，必须重做第七节的评估——不能只改仓库可见性。

## 九、备份：默认不加密的取舍

- **默认行为**：普通 `.7z`，无密码，双击即开；只有显式 `-Encrypt` 才走 AES-256 + `-mhe=on`。
- **为什么**：普通人丢密码 = 数据永久锁死；加密包在换机、网盘、手机上可用性差。
- **风险**：未加密包就是**明文观看史**。同机其他账户、网盘服务商、丢失/转卖的移动盘，都能直接读。
- **缓解**：离机备份加 `-Encrypt`；至少开 BitLocker/FileVault；不要把未加密包放公共网盘；备份目标越少越好。
- **定性**：这是可用性与机密性的显式取舍，不是"安全默认"。README 首屏与备份一节都标注了；工具提醒，但不替用户决定。

## 十、提示注入与 AI 自动化

- **威胁**：视频标题、简介、动态文字、私信正文都由第三方控制。AI 若同时具备"读归档 + 执行命令 + 联网"，可能被其中一段文字诱导去删文件、发消息或上传数据。
- **工具措施**：只读接口、无发送/上传能力、分享 HTML 对标题做转义、`-NoTitles` 可隐去标题；工具自身不执行任何抓取文本。
- **用户措施**：见 [`提示注入防护.md`](提示注入防护.md)——把抓取文本当数据、最小权限、三选二、人工确认外部动作。
- **边界**：工具不做"注入文本识别"（没有可靠通用规则），也不替 AI 做信任判断；它只负责标注"这是不可信输入"。

## 十二、AI 使用：声明与三问

本工具不判断 AI 可不可信，也不提供强制降权开关——有 shell 权限的 AI 本来就能绕过参数。能起作用的是三件事：**默认值、风险声明、向 AI 提问**。

### 默认值

- 采集与备份只落本地，不联网上传；除 `登录态\` 外不读任何凭据。
- 把数据交给 AI 前，先去掉标题、UP 名、UID、BVID 与收藏夹名——它们既能定位你，也是提示注入的载体。
- 不了解风险的使用者（孩子、长辈、第一次把归档交给 AI 的人），先只给聚合统计，不要整份 jsonl。

### 放开档

满足三条即可把逐条数据交给 AI：① 人读过本文档与 [`提示注入防护`](提示注入防护.md)；② AI 答得出下面的"三问"；③ 不可逆操作仍由人确认。放开后可用 `query.ps1 -Json` 取数，或让本地模型直读 jsonl。

### 三问（任何要碰归档的 AI 都要答）

1. 这些数据离开本机会怎样？
2. 你打算把它发给谁？
3. 哪些操作你会先停下来问我？

答"放心没问题"、说不清流向、或反过来索要 cookie / 登录态目录的，不要让它碰归档。

### 不承诺的事

- 无法强制 AI 只用聚合数据；工具只能保证"默认不外发"。
- 不代扫码、不代持凭据（技术上也不行：二维码必须人扫）。
- 不替 AI 判断"可不可信"；这由人用三问去试。

### 残余风险（做了上面也还在）

1. **聚合本身也是画像**：30 天的分区、时段、完成度足以推断作息与兴趣；脱敏只降低粒度，不消除推断。
2. **模型侧的日志**：请求一旦离开本机，供应商是否留存不归本工具管。
3. **提示注入无法根除**：标注"不可信"只是提示，不是过滤器；放开档下必须保证"读归档 + 执行命令 + 联网"不三者同时具备。
4. **人工复核点变少**：唯一稳定的人工闸门是"不可逆操作确认"，这一条不能省。
