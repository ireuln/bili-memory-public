# 扩展点：这是一份基座，不是封顶

> 这个仓库的目标不是“只做这几件事”，而是把**可复用的结构**留出来：数据契约、查询接口、采集分支、模板与语言包。
> 你可以在此基础上接自己的采集源、输出格式、分析器或界面；本仓库不提供敏感实现，但也不把扩展点封死。

## 一、数据契约

所有产出都是本地纯文本：

- `<DataRoot>/观看记录/YYYY-MM.jsonl`
- `<DataRoot>/收藏备份/收藏总表.jsonl`
- `<DataRoot>/关注/members.jsonl`
- `<DataRoot>/last-result.json`

字段、单位、空值与退出码见 [`数据契约.md`](数据契约.md)。**先读契约，再写解析**；不要按某次运行的样本猜字段。

## 二、查询接口

`query.ps1` 是稳定的只读取数层：

```powershell
.\query.ps1 -From 2026-10-01 -Json
.\query.ps1 -Source fav -Folder <夹名> -Table
.\query.ps1 -Title <关键词> -OutList bvids.txt
```

- 默认输出 `{schema:1, matched, returned, items:[...]}`；
- 两种来源共用同一套字段名；
- 只读、不联网、不写 `DataRoot`。

其他程序或 AI 应当走这个接口，而不是自己解析 jsonl——排序、去重与完成度兜底都在里面。

## 三、采集扩展

`collect.ps1` 的每个采集模式都是同一个形状：

1. 在 `$Js*` 块里定义“在浏览器页面内取什么”；
2. 在 `main` 里加一个 `-Mode` 分支；
3. 把结果写成 UTF-8 无 BOM 的 jsonl；
4. 写 `last-result.json`，显式 `exit 0`。

模板与编码/变量名陷阱见 [`AI-交接说明.md`](AI-交接说明.md)。**具体接口的请求形态不在文档里展开**：新增采集源前，先确认它是否属于本人账号可见的数据，再自行确认请求是否可用。

## 四、输出与界面

| 想改 | 接在哪 |
|---|---|
| 分享卡片 / 文案 | `share/` 模板 + `config.json` 的 `Share` 段 |
| 统计报告 | `report.ps1` + `config.json` 的 `Report` 段 |
| 托盘菜单 / 提示 | `tray.ps1` + `config.json` 的 `Tray` 段 |
| 界面语言 | `lang/*.json`；只改显示文案，不动数据目录 |
| 备份目标 | `config.json` 的 `BackupTargets`；同卷自动硬链接 |

## 五、边界（不是封顶，是责任边界）

- 本仓库不内置批量下载、自动发送、上传或云同步；这些动作会改变外部状态，应由使用者自己决定是否接、怎么接。
- 不采集他人账号的数据；不绕过付费、权限、地区限制或认证机制。
- 外部工具如果自己保存登录态，不要把本工具的登录态目录交给它；两套边界不要混用。
- 非官方修改版请改名并去掉本项目标识，避免用户分不清谁签发。

## 六、怎么贡献

- 先读 [`PR审查清单.md`](PR审查清单.md) 与 [`../CONTRIBUTING.md`](../CONTRIBUTING.md)；
- 一个 PR 只做一件事；新增第三方代码先确认许可；
- 改动涉及数据格式时，先改 [`数据契约.md`](数据契约.md)，再改代码。
