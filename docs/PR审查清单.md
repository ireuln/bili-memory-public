# PR / 贡献代码审查清单

> 目的：这个仓库会被人下载并**在全量权限下运行**（读你的归档、写你的盘、注册计划任务）。
> 所以合并任何外部改动，都要按下面的顺序过一遍。**一票否决项优先于一切理由。**
> 维护者是自己一个人时也照样走一遍——防的不是"坏人"，是"手滑"和"AI 生成的看起来对但其实有后门"。

## 使用主体（先于一切）

任何新功能、新参数、新脚本，先回答六个问题：

1. 它处理谁的数据？
2. 谁发起这个动作？
3. 数据会不会离开本地？
4. 会不会改变外部状态（发布、发送、写平台）？
5. 默认开还是关？关的时候用户怎么知道？
6. 公开文档只写哪一句？

答不出“本人、本地、只读”的，按 [`安全与边界.md`](安全与边界.md) 判断；
跨到对方、第三方、公众或平台的，默认不进本仓库，除非有明确隔离与默认关闭。

## 0. 三十秒初筛

```powershell
gh pr diff <编号> --repo ireuln/bili-memory-public
gh pr diff <编号> --repo ireuln/bili-memory-public --name-only
```

- 只改文档 / 语言包 / 注释 → 可以快过；
- 有任何文件落在下面这些目录，**逐行读**：
  `collect.ps1`、`run-task.ps1`、`backup-*.ps1`、`tray.ps1`、`setup.ps1`、`uninstall.ps1`、`register-task.ps1`、`lib\`、`src\`

## 1. 一票否决项（出现任一条就关掉 PR）

| # | 红旗 | 为什么 |
|---|---|---|
| 1 | 新增**域名 / URL**（除 `api.bilibili.com`、`www.bilibili.com`、`api.github.com`、`127.0.0.1`） | 数据外传的唯一通道 |
| 2 | `-EncodedCommand`、`FromBase64String`、`iex`、`Invoke-Expression` | 混淆执行，人读不出来 |
| 3 | 读 `登录态\`、`Login Data`、`Cookies`、`SESSDATA`、`bili_jct` | 凭据即账号 |
| 4 | 新增注册表写入、启动项、计划任务（`register-task.ps1` 之外的） | 持久化 |
| 5 | `RunAs`、`-Verb RunAs`、UAC 绕过 | 提权 |
| 6 | 新增二进制 / EXE / 压缩包且无对应源码 | 无法审查 |
| 7 | 改动 `.githooks/`、`tools/check-secrets.ps1`、`SHA256SUMS.txt` 或构建脚本 | 等于改闸门本身 |
| 8 | 删除或弱化现有安全检查（脱敏、路径守卫、`$unsafe` 列表） | 常见"顺手简化" |

## 2. 必跑三项

```powershell
powershell -File .\tools\check-secrets.ps1        # 密钥
powershell -File .\selftest.ps1                    # 配置/目录/只读接口
powershell -File .\build-release.ps1 ; .\dist\...\verify-files.ps1
```

CI 没跑也无所谓，这三条必须本地都 exit 0。**发布包和源码行为不一致是本仓库历史上最大的一类 bug**（`share\` 漏打包那次）。

## 3. 许可与署名

- 新增第三方代码：必须有 `LICENSE` 或仓库 API 认定为兼容许可；**只有 `package.json` 字段不算**；
- 同时改 `docs/致谢.md` 与 `README.md`（项目 / 作者 / 许可 / 用途 / 改动）；
- 无许可 = 保留所有权利，一行都不能抄；不确定就先关掉 PR 问清楚。

## 4. 合并动作（顺序不能反）

1. **Squash merge**（保持提交历史可读，也避免别人的提交里夹带东西）；
2. 合并**前**记下自己审过的提交 SHA，合并后 `git log -1 --stat` 核对内容一致；
3. 合并后立刻跑一次 `selftest`；
4. 只有要发版时才打 tag + Release，Release 说明里写清"本次引入的外部代码"。

## 5. 内容注入（不是代码，但也算注入）

- 抓下来的标题 / 简介 / 动态文字一律视为**不可信数据**，只展示、不执行（见 [提示注入防护](安全与边界.md)）；
- 不要把这些原文直接贴进 issue，或整段丢给 AI 让它"照着做"——那是把别人的指令送进自己的执行链。

## 6. 给贡献者的话（可贴进 PR 回复）

> 谢谢！合并前我会过一遍安全清单（外联域名、混淆执行、凭据读取、持久化、提权、二进制）。
> 麻烦补一句：这次改动你是否用 AI 生成/辅助？用到了哪些模型？——不影响是否合并，只影响我审得多细。

## 7. 公开文档的措辞（风险相关）

公开文档只描述**发布物**，不描述私有实现、私人行为与法律定性：

- 只写否定陈述（"不含 / 不提供 / 不实现"），不写"我还留着 / 我在本机用"这类私人行为；
- 不给自己贴法律定性术语（如"规避""破解"）；引用对方定性时加引号、注明出处；
- 不写私有代码的规模、函数名、调用次数——这类"系统性整理"正是先例点名的行为；
- 不给不存在的实现排风险等级（"风险最高 / 核心风险"），也不写"本文不展开"这类围绕被移除能力的提示；
- 不承诺未来行为（"只在本机使用""永不外传"）：无法验证的承诺比不说更糟；
- 必须提到敏感能力时，只写"不在本仓库"，不写怎么用、接在哪；
- 不写预设另一个版本存在的说法：直接说"本仓库不含 / 本仓库没有"。

**平台条款（写文档时）**：

- 只写条款号 + 一句转述 + "风险自担、自行判断"，**不写"合规"结论**，也不写"平台不管"这类判断；
- 条款**不当硬墙**：功能取舍仍按"本人 / 本地 / 只读"三条判断，条款只影响文档措辞与默认开关，不成为删功能的理由；
- 引用条款时注明版本与来源，条款更新后回头改这一句，不改功能。
